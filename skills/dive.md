# Dive: 번호 기반 컨텍스트 다이브

$ARGUMENTS 값에 따라 동작이 달라집니다.

---

## 모드 판별

- `$ARGUMENTS`가 **비어 있거나 텍스트**인 경우 → **목차 생성 모드**
- `$ARGUMENTS`가 **숫자**인 경우 → **다이브 모드**

---

## 모드 1: 목차 생성

`/dive` 또는 `/dive 지금까지 논의한 내용` 처럼 호출된 경우.

### 실행
1. 현재 대화에서 탐구할 만한 주제들을 식별하세요.
2. 번호 매긴 목차를 만들어 사용자에게 보여주세요.

### 출력 형식
```
📋 다이브 목차:
[1] 주제 A — 한 줄 설명
[2] 주제 B — 한 줄 설명
[3] 주제 C — 한 줄 설명
[4] 주제 D — 한 줄 설명

→ /dive [번호] 로 탐구하세요.
```

### 목차 작성 원칙
- 대화에서 **깊이 파볼 만한** 주제만 선별 (사소한 건 제외)
- 각 항목은 **독립적으로 탐구 가능한** 단위로
- 4~8개 사이가 적당
- $ARGUMENTS에 텍스트가 있으면 그 범위에 맞춰서 목차를 좁힐 것

---

## 모드 2: 다이브

`/dive 2` 처럼 숫자로 호출된 경우.

### 실행 절차

#### 1단계: 맥락 추출
목차에서 해당 번호의 주제를 찾고, 현재 대화에서 관련 내용을 파악하세요:
- 핵심 결정사항, 코드, 아이디어
- 아직 해결되지 않은 질문이나 논점
- 관련 파일 경로, 코드 스니펫

#### 2단계: 서브에이전트 스폰
Task tool로 `general-purpose` 에이전트를 스폰하세요. 프롬프트 구성:

```
[배경 맥락]
현재 대화에서 추출한 관련 내용. 코드, 파일 경로, 결정사항 등 구체적으로.

[탐구 주제]
목차 N번 항목의 주제와 구체적 질문.

[요청]
- 위 맥락을 바탕으로 깊이 있게 분석해.
- 코드베이스 탐색이 필요하면 Glob, Grep, Read를 적극 활용해.
- 결과는 핵심만 간결하게 정리해서 반환해.
- 한국어로 응답하되, 코드와 기술 용어는 영어 그대로.
```

#### 3단계: 결과 + 남은 목차 표시
서브에이전트 결과를 사용자에게 보고한 뒤, **반드시 남은 목차를 다시 표시**하세요.

### 출력 형식
```
## [N] 주제 — 다이브 결과

(서브에이전트 분석 결과 요약)

---
📋 남은 목차:
[1] 주제 A — 한 줄 설명
[3] 주제 C — 한 줄 설명
[4] 주제 D — 한 줄 설명

→ /dive [번호] 로 계속 탐구하세요.
```

이미 다이브한 항목은 목차에서 제거하세요.

---

## 핵심 원칙

- **스크롤 제로**: 다이브 결과 끝에 항상 남은 목차를 붙여서, 사용자가 위로 스크롤할 필요 없게 한다.
- **컨텍스트 보호**: 깊은 탐구는 서브에이전트 안에서. 메인 대화에는 결과 요약만 남긴다.
- **충분한 맥락 전달**: 서브에이전트가 독립적으로 작업할 수 있도록 배경 정보를 프롬프트에 충분히 포함한다.
- **간결한 반환**: 장황한 분석 전문이 아닌, 핵심 인사이트와 결론 위주로 보고한다.
- **한국어 응답**: 사용자에게는 한국어로 보고하되, 코드와 기술 용어는 영어 그대로 사용한다.
